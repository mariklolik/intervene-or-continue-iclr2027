We introduced a repeated-branch protocol that separates the continuation used to choose a runtime repair from the one used to value it, and a reading of the same branches that says how much per-task signal a decision point and a menu carry before a controller is fitted. On the first frozen panel the protocol establishes a 15.36-point gap between same-draw maximization and independent-draw evaluation, and a within-task exchangeable-label reference places 17.26 points of it in continuation noise rather than in action advantage. Where a complete independent draw of the menu cannot beat the best arm in hindsight, the per-task outcome signal is thinner than the menu average, and on a panel run under both checkpoint rules with one menu that is what separates them. Moving the decision to the first public failure signal and separating repair depth from repair content lifts that reference to 50.80\% against 49.09\%, and a controller that chooses its action on one development draw and values it on another changes success by 1.26 points against continuation and by 1.94 points against the best fixed repair. Runtime controllers should include no action, freeze their choices before outcomes, value them on draws not used for selection, and read what the decision point and the menu carry before blaming the learner for a null.
